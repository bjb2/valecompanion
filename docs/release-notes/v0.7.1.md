Vale Companion 0.7.1 restores protocol compatibility with SpiritVale 0.33.0 Early Access (Steam build 25647861).

## Changes

- **Market capture compatibility:** Refreshed shifted RPC IDs so in-game market searches and listing responses are recognized again.
- **Complete supported RPC-map refresh:** Recovered 385 RPC registrations across 16 behaviours, including six newly added RPCs and inherited registrations. Verified the existing 51 SyncType indices, six broadcast keys, and six supported prefab layouts against the matching game binary and asset export.
- **Updated wire payloads:** Consumable-use requests now decode their item count. Damage and death payloads include the new `IsAutocast` flag without misaligning subsequent fields.
- **Traceable build identity:** Updated the canonical map's binary-pair fingerprint and recorded source hashes and recovery evidence. Static item and map-name snapshots retain their separate provenance.

## Updating

Installed users can choose Settings > Check for updates, then Update and restart. For manual Windows installation, choose `ValeCompanion-0.7.1-windows-x64-setup.exe`. Portable users should close Companion and replace the executable while preserving their data folder. No profile, filter, or overlay-settings migration is required.

Restart Companion after updating. If attaching while already in game, change maps or reconnect to establish fresh inventory and RPC-link state.

Windows binaries are unsigned and require Npcap installed separately. Linux downloads include AppImage, DEB, and RPM. Matching source, updater metadata, blockmaps, and `SHA256SUMS.txt` are included.

## Validation

Map validation, typechecking, all 146 tests, and the application build passed locally. New regressions cover current-build market request/response routing, stacked consumable counts, and damage-field alignment. Refreshing the released SpiritValers catalog reproduced the existing 2,513 entries with no added, removed, or changed catalog entries.

Local Windows installer and portable packaging completed. The portable collector/renderer smoke test, game-artwork loading, second-launch resource checks, and release-artifact/updater-metadata verification passed.

Live Windows testing confirmed inventory and personal-storage snapshots, pickup alerts, gold and kill updates, and four market response pages containing 88 listings. All 88 listings normalized without market errors; test observations were not uploaded. One inventory snapshot was partial, and subsequent snapshots populated the bag. Consumable counts and damage-field alignment were tested with synthetic packets rather than separately confirmed in game.

The release workflow gates publication on native Windows and Linux builds, packaged startup checks, and artifact/updater-metadata verification. Full Linux gameplay and a version-to-version installed update are not covered by the local gameplay checks.
